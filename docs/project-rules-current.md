# 当前业务约定

> 2026-10-24 从项目规则历史中提炼。本文维护当前有效行为，根目录 AGENTS.md 为入口。下文“不恢复”“保留”等要求约束未获授权的回退，不阻止用户明确要求的新变更；业务变化更新对应条款，历史存档中的相反指令不自动生效。专题文档用于展开细节，其中旧状态、尺寸和实施记录须核对本文件及实际配置。本文整理不授权运行生成、修改数据库或重做历史作品。

## 批量任务与状态

- 备料区在“已选 × 条”操作行提供“暂停备料 / 继续备料”，未勾选时也保留入口，控制整批备料。暂停不打断当前备料或出片请求，等当前条目安全结束后停止后续任务；界面区分正在暂停与已暂停，已暂停后可重启项目。暂停状态持久保存，重启后不自动开跑，用户点继续后沿用已有素材和请求检查点恢复。
- 备料区不显示单条或批量“跳过”和“重新开始”操作；暂停后只需点“继续备料”恢复。其他区域的跳过和异常重试规则保持不变。
- 备料区每条任务右侧提供单条“暂停 / 继续”。单条暂停持久保存并从调度中排除，不阻断其他条目备料；当前下载结束后可暂停在生图前，已提交的生图请求安全收尾后保留结果。单条继续只解除该条暂停，不解除整批暂停；暂停条目留在备料区，解除后已备齐的素材直接进入等待区。
- 一个批次同时容纳 singing/dance，备料可以先完成，视频生成与交付严格单链路。人物图与发布文案齐备即 `prepReady`，缺封面不影响出片准备状态。
- 备料完成的 `confirmed` 默认 `renderQueued=False`，进入等待区；只有手动“已安排出片”逐条设置排队并启动。等待区有勾选时安排所选，否则安排该区全部。出片区跳过后可以重新安排；旧批次 `autoRender` 不得绕过逐条安排。
- 安排出片的请求只更新排队和编号，不等待整批素材复制；视频 runner 轮到当前条目后再把该条素材写入正式发布目录。
- 动作响应、HTTP 分区及 WebSocket 首帧和后续推送均需携带 `prepReady` / `publishChain`，不能依赖下一次轮询纠正条目分区。订阅只保留最新快照，已删除条目不推送。
- 只保留最新批次未删除条目；整批删空也删除批次行。并发 update/mutate 一次读写且锁覆盖整个修改，数据库连接可靠关闭。取消、交付、封面回调尚需使用的记录临时保护，收尾后再清理；不得因清理历史误删作品文件。
- “标记已完成”只改状态、登记已存在文件，不生成或删除文件。允许 failed/skipped/confirmed，completed 幂等；运行或修改中的任务先取消，deleted 拒绝。没有成片时说明现状，之后放入真实成片仍应能查看。
- 查看成片同时识别 `outputs.videoFinal` 与发布目录实际文件；路径访问必须限制在发布根内。标题统一以 `ai.title` 为准，列表、文案和目录不得各用不同标题。
- 失败时保留真实原因及诊断信息；进度使用真实节点、帧数或阶段数据，无进度数据时显示阶段，禁止伪造百分比。runner 接管需保留代数守卫，旧 runner 不得覆盖新一轮状态。
- 备料完成后关机、全部完成后关机默认关闭，保留互斥、暂停保护、60 秒可取消倒计时。备料关机可将失败、跳过、已完成视作本轮结束，但不把异常计为成功出片；无有效条目不触发，仍排队、备料、待确认、实际运行和后台封面均须按各自关机条件判断，不能仅凭页面没有运行行就认定可关机。

## 源视频与发布目录

- 跳舞时长上限遵循根规则；下载后备料前、本机替换、独立动作迁移上传/重跑和出片前的校验不能遗漏，也不能推迟到付费生图之后。
- 新建或追加时，同一链接若同时出现在唱歌和跳舞输入中，两边均过滤；全部过滤则明确报错，不擅自决定类型。既有批次不追溯删除。
- 新建和追加共用 `data/douyin-link-history.db` 长期链接记录，按去掉首尾空格后的原链接比较，不为此解析作品 ID 或请求抖音。同一链接不因删除条目、清理批次或切换唱歌/跳舞而再次入队；失败任务可在原条目重试。首次建立记录时补入现有批次和下载记录中的链接（含失败记录），无法据此保证已丢失的全部历史均可追溯；不同短链接不会由长期记录合并。只有成功入队的链接登记，同批输入被过滤的未接收链接不登记；原有批次内归一化及下载后作品号检查保留。
- 添加任务的响应逐条返回重复链接、输入类型与序号、过滤原因；添加窗口显示实际新增数和重复清单。有重复项时不自动关闭；全部重复时保留输入，部分成功时只按原有草稿保护规则清空本次提交的输入。清单仅属于这次操作，不写入批次长期状态；重新打开添加窗口时清空上次结果和重复清单，不反复显示已看过的提示。
- 本地已有同作品的视频优先复用，不重复下载。下载报错保留直连和下载器兜底的实际原因，不用统一 Cookie 提示掩盖问题；状态查询不应擅自启动下载服务。
- 默认发布根见 `settings.BATCH_OUTPUT_ROOT`（通常 `E:\AI_Exports\H3-MotionStudio\发布成品`）。新目录位于 `singing/`、`dance/`，编号取类型内 `kindIndex`，三位补零，无该字段的历史条目退回 `index`。已删除条目不占新编号，清空后新任务可从 001 开始，不顺手改写仍在用的条目编号。
- 一个条目复用一个发布目录，优先已有 `outputs.folder`。扫描类型子目录优先、旧扁平根兜底；历史目录不批量迁移或改名。只读检查不能调用带改名副作用的 `publish_folder()`。
- 人物图、发布文案在备料/审核时落盘，交付写 `最终成片.mp4`；源 `抽帧.jpg` 保留。重试先核查真实文件，只补缺失项；更新文案或刷新物料不删除已有图片、封面。
- 已生成封面或有明确文案锁定标记时保持封面与文案一致，不无故重写标题。替换人物图应更新真实输入和相关缓存；已付费请求仍按冻结输入恢复，不能拿新图覆盖旧请求的参考。
- 本机替换源视频保留用户已设置的其他内容，并更新源卡片、清除失效的抖音身份。替换链接与本机文件有不同的重备料语义，不能合并为无差别重置。

## 人物图、抽帧与身份

- 复用现有全帧扫描与评分：45 秒及以下逐帧、90 秒及以下每 2 帧、更长每 3 帧；评分保留少量最高候选，失败才回退采样。不存在“首帧有人物直接采用”规则。不要为封面恢复已经移除的成片选帧链。
- 人物生图的图一使用源抽帧处理副本，全部检测人脸沿用整脸高斯模糊；图二为唯一面部身份参考且不模糊。SCRFD/定位失败停止提交，不能退回未经糊脸原图；缓存需验证源图更新，所有自动、手动素材和旧入口一致。
- 不调整现有糊脸范围、强度、外扩或羽化，不恢复只糊五官和已糊脸源视频专用绕过。源图与处理图分开保存，方向按 EXIF 校正，写文件保持原子性。
- 人物图提示词统一复用 `batch_ai.compose_image_prompt()` 及已有公共块；生成、复制和素材包共用，不分别维护同义提示词。YeeMagine 是 GPT 图像接口中转站，按 GPT 图像模型写提示词，不发明渠道专属风格；造型来源模式、具体发型配饰规则以当前提示词及 `docs/source-appearance.md` 为准，不把某次造型实验推广到所有模式。
- 人物图场景以符合本次服装风格、配色、材质与人物整体气质为准；画面中不出现床、床垫、床头、沙发或躺椅，人物身后及两侧简洁通畅；原图存在这些物品时移除并补全原有墙面和地面，居家场景保持真实自然，不用虚化掩盖。必须替换源抽帧背景，重新设计与穿搭协调且明显不同的新场景；即使原背景合适也不得沿用，不得只清理杂物、换色或虚化，不强制保留原室内外类别。环境色彩、陈设与空间氛围衬托人物，人物与环境的光向、色温、投影和透视一致。歌曲重设计模式同时考虑歌曲氛围。已有图片不自动重做，已提交任务继续使用冻结提示词。
- 保持写实日常风格、清楚空间和自然光，不默认改成舞台或广告大片。图二只锁定面部身份，不照搬其服装、发型和背景。自然妆感、脸颈一致、可见手部和衣肤边界清晰。
- 唱歌 4:3 保持近景、跳舞 9:16 保持既定裁切；不重新加入跳舞脸高 34% 等冲突尺寸。手部只约束可见区域，画外手不补入；面部完整可见优先于参考姿势，手或前臂遮脸时必须自然放下或移至脸侧，露出双眼、鼻、嘴和下颌，不照搬遮脸动作；修改意见覆盖同类默认要求，身份与服装覆盖底线仍生效。
- 服装覆盖要求唱歌/跳舞共用，不机械限定长裤、过膝裙或袖型；跳舞补充活动时覆盖。具体要求见 `docs/person-image-prompts.md`。
- 不恢复人物图生成后的自动身份评分重做、手部视觉自检重绘或已暂停的局部修手实验；普通代码与提示词验证不调用真实付费生图或改写旧作品；用户明确授权实测时，严格限定作品、请求范围和既有成本保护。

## 图片计费、尺寸与恢复

- 新图片请求共用当前 `image_sizes` 定义：4:3 为 3264×2448，3:4 为 2448×3264，9:16 为 2160×3840；人物图跳过本地放大，封面原图直存。当前模型约定为 `gpt-image-2`，不因截图或渠道新型号擅自切换。
- 尺寸是项目请求约定，不代表渠道支持已实测。旧 1K/2K 已付费任务仅在除尺寸外输入指纹全部相同时沿用原指纹恢复，不能改尺寸后重发。
- 图片页单条“补齐这条的缺图”为用户主动重提：已有图片跳过，缺图的旧请求归档后重新提交，可能产生新费用；已下载的封面原图只补保存。自动恢复和一键补齐仍续取原任务。
- 跨批量、图片页、重试与旧入口共用去重、检查点和请求冻结。保存参考图、提示词、比例、任务 ID 与已下载结果；取消、超时、重启、查询/下载失败或未知结果不得触发新的计费提交。
- 任务目录 `.h3-{stage}-work` 和 pending 标记在结果未确认时保留，不作为普通缓存清理；有原图只补落盘。没有任务 ID 或可用原图的未知 pending 需人工核对，不自动重发。可靠交付后的清理和明确拒绝处理沿用现有终态逻辑。
- 仅中转站明确返回封面终态失败时，该张可换备用提示词再提交一次；备用标记和终态持久化，备用再失败不循环，另一张成功封面不重做。此例外不适用于超时或不确定状态。

## 封面

- 自动触发时机遵循根规则：只为当前成功提交视频任务的条目后台生成；交付后补缺。页面手动生成、补齐缺图入口不要求先有成片，已有封面跳过。
- 唯一参考是原人物图，不糊脸、不附身份图，不取成片帧。生成前检查手指连接/数量、左右掌背、手腕与遮挡，并独立检查伸臂出画/手部贴边；同图片内容两种比例共用检查缓存，现行缓存为 v3。
- 手部合理且无伸臂出画风险时保留原构图；手部结构合理、手指完整但贴边或有伸臂出画风险时，保留原动作，适当缩小并调整人物位置，必要时仅延展同场景背景，使原有可见双臂、手腕、手掌和全部手指完整入画，与四周保留至少 5% 安全边距，不以藏手或放下手臂解决贴边。手部不合理、截指、不确定、检查失败或终态失败备用时可调整双臂自然下垂；画内出现袖口或手腕时必须自然连接完整双手，近景裁切须在远离手腕的前臂或上臂处，使袖口、手腕和双手一起出画，禁止空袖口、腕部截断或只删除手掌。补全原遮挡的服装与背景，不改变五官身份。
- 默认 B站为 4:3 胸部以上近景、脸部突出，文字可放人物一侧；不恢复展示到腰、肩宽 35%~45% 等缩小人物约束。抖音为 3:4 半身构图。优先调整文字，不为文字留白扩背景或缩小人物；为手部安全边距调整构图时按上一条执行。
- 封面沿用人物身份、发型、服装与场景，采用既有自然手写毛笔标题、重点词配色和轻量简介；文字装饰避开人物，不加平台 logo。不自动生成 16:9 封面或其他比例。
- 生成结果直接保存渠道原始字节，不二次放大、裁切、重新编码或视觉复查，不生成成图手部报告。失败不把已交付视频改为失败；后台任务去重，整批结束和自动关机等待其收尾。
- 新图片请求提交前检查实际线路（含强制代理），不通时先用只读探测验证备用线路；两条都不通则不提交。封面失败按平台持久记录并在批量列表显示“封面待处理”，保存成功后清除对应提醒。未收到接单回执只能标为受理未知，不能声称已提交成功，也不得直接重发可能已计费的请求。
- 自动生成、复制提示词和素材包共用当前提示词函数；历史已付费请求即使冻结旧双参考或旧构图，也按原输入续取，不回溯重做已有封面。

## 发布文案、字幕与音色

- 标题、简介和标签健康友善、正向。原标题和简介仅作主题与事实参考，结合我们最终人物图、歌曲或舞蹈及作品看点重新创作适合我们自己作品的新文案，不直接沿用原句或仅换词、调语序、标点；歌名、舞种等准确事实可保留，标签仍可参考有效原标签。模型不可用时使用中性兜底，不复制或引用源描述；简介不留空、标签补齐到 5 个，不添加无关平台字样。
- 与原作者本人强绑定的私人经历、强烈情感、自我感慨、纪念、身份或人际关系表达直接舍弃，不换人称、同义改写或泛化为送给所有人；删除明确自述的个人引流及相关标签，不凭 @昵称猜测账号关联。依据视频实际内容重新拟写，不编造故事；与视频本身有关的普通情绪可以保留。主题与事实参考同样遵守本条，细节见 `docs/publish-copy-safety.md`。
- 使用创作者口吻，避免人物画面说明和模板化互动号召。跳舞使用舞蹈/手势舞等语义，不写翻唱。文案规则统一在生成提示词、本地清理、源标签和兜底路径生效，细节见 `docs/publish-copy-safety.md`。
- `/subtitle` 沿用剪映识别时间轴，歌词核对只改文字，不重新对齐、插值或改时间节点；保留当前歌词来源及比对链路，不恢复已下线 `/lyrics` 的方案。
- 字幕一键批量只处理唱歌目录中有最终成片且缺字幕版的作品，按现有暂停/继续规则逐条执行。输出 `最终成片_字幕版.mp4` 与无字幕成片并存，已有字幕跳过；交付到原作品目录不得顺手改名，复制失败保留可下载结果并报告。
- 保留剪映现有版本及更新锁定，不擅自升级。草稿重建、窗口关闭、超时、取消与重试须沿用现有保护，不能删除用户真实草稿；排障先核对当前自动化方式，历史记录里的旧草稿模板或鼠标坐标不直接照搬。
- 当前 RVC 默认为 `mogoo_48k_v2`，以 `settings.RVC_MODEL` / `RVC_INDEX` 核对，输出按模型原生采样率；保留旧模型和索引，不恢复旧固定 40k 输出。移调及其他参数不按歌曲自行猜测调整。模型名称和采样率是当前约定，后续经用户授权切换时同步更新本条，不能依旧文本改回旧配置。
- 项目调用的 RVC 脚本与便携音色转换器属于不同程序，部分权重目录共享；仓库外脚本或模型变更需确认影响、先备份，运行中的 RVC 不修改。不得将仓库提交视为已备份外部程序。

## 界面约定

- 保持现有灰绿深色工作台、精简侧栏与组件体系。品牌角色沿用当前分配和互动，不因历史“成对互换”记录再次交换。
