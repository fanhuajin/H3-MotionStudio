## 二、这台机器上驱动剪映的硬规则（全是实测踩出来的）

### 1. 点击必须"像真人"
- **只用真实鼠标**：`SetCursorPos` + `mouse_event`（分步渐进移动，每步 ~12ms），落点前**停顿** 0.3~0.6s，再按下/抬起。
- **PostMessage（`post_click`）对自绘控件无效**：
  - 字号 spinner 点了 5 次，`font_size` 一直 5.0；
  - 字体下拉里投递点击，浮层直接当"框外点击"关闭；
  - 首页「开始创作」和素材「+ 导入」那次侥幸生效，但**不能依赖**。
- **浮层/下拉要多停**：先移到目标旁边停一下，再落到点上停一下，最后才点击；否则浮层自我关闭。

### 2. 点击前必须确认真实前台窗口
- 本次最大的一次翻车：**前台一直是 Edge**，`force_foreground()` 报 True 但实际没抢到前台，
  于是所有点击都打到浏览器上（表现为"怎么点都不中"）。
- 可靠做法（`AttachThreadInput` + `SetForegroundWindow` + `BringWindowToTop`）：
  ```python
  tid_t = user32.GetWindowThreadProcessId(hwnd, None)
  tid_f = user32.GetWindowThreadProcessId(user32.GetForegroundWindow(), None)
  tid_s = kernel32.GetCurrentThreadId()
  for tid in {tid_t, tid_f, tid_s}:
      user32.AttachThreadInput(tid_s, tid, True)
  user32.BringWindowToTop(hwnd); user32.SetForegroundWindow(hwnd); user32.SetActiveWindow(hwnd)
  # …再逐个 AttachThreadInput(..., False) 解绑
  ```
  **切完必须校验** `GetForegroundWindow() == 剪映主窗口`，不成立就不点。

### 3. 截图不可信，读数走 UIA
- `grab_screen()`（屏幕取像素）会抓到**压在剪映上面的浏览器**；
- `capture()`（PrintWindow）可能返回**陈旧帧**（同一画面两次抓取 diff=0.0 而实际已变）。
- 可靠的读数：
  - 播放头 `currentProgress|hh:mm:ss:ff`、总长 `totalProgress|…`（TextControl）；
  - **属性面板文案框**：`EditControl`，窗口内约 (2510,214)-(3422,294)，**支持 ValuePattern 读/写**；
  - 面板其余输入框（字号数值位 (2585,1025)-(2653,1052)、X/Y 等）是 QML 自绘，UIA 只能读到 `value`，写不进去。

### 4. 片段行坐标（本次实测）
- 文本轨可点行：**y ≈ 1035**（1020/1060 偶尔能中，1030~1050 反而常空）；
- 文本轨 x↔时间：线性，第 1 段中心 x≈312 ↔ 3.0s，7 段中心 x ≈ 312 / 428 / 616 / 746 / 918 / 1098 / 1226；
- 验证命中不要靠截图：**点完读播放头时间**，落在该句区间内才算点中。

### 5. 键盘输入
- 纯数字/短文本用 `type_number()`（pywinauto 真实按键：Ctrl+A → Delete → 键入）；
- **中文/长路径不要用键盘直打**：`jy.paste_text()` 在这台机器上直接抛
  `pywintypes.error (6, 'SetClipboardData', '句柄无效')`（剪贴板句柄拿不到）。

## 三、和 `/subtitle` 自动链路逐项对照

`/subtitle`（`POST /api/jobs/subtitle` → `subtitle_step.run_subtitle_job()` → `burn_for_video()`）
三步：`recognize`（剪映识别歌词）→ `verify`（网易云官方歌词只核对文字）→ `burn`（ffmpeg + 剪映手书烧录）。

| 手工步骤 | 自动链路里对应实现 | 状态 |
|---|---|---|
| 1 打开剪映 | `jianying_uia.ensure_app_accessibility()`（带 `QT_ACCESSIBILITY=1` 拉起） | ✅ 已自动化 |
| 2 开始创作 / 导入素材 / 加到时间轴 | **完全跳过**：`jianying_recognize.clone_draft()` 克隆 `data/jianying_template` 骨架，直接写 `draft_content.json`（素材路径 + 时长 + 画布 + 清空旧文本轨） | ✅ 更稳（纯文件操作，不用点 UI） |
| 3 选文件 | 同上（源片已在任务目录 `data/subtitle/{job}/source*`） | ✅ |
| 6 切「文本」页签 | `jy.post_click(hwnd, *jr.TEXT_TAB)`，`TEXT_TAB=(194,60)` | ⚠️ 靠投递消息，本次实测**该坐标本身有效**（我真实点击同点成功），但投递方式在自绘控件上不可靠 |
| 7 点「识别歌词」 | `jy.post_click(hwnd, *jr.RECOGNIZE_ITEM)`，`RECOGNIZE_ITEM=(87,343)`（实测该项中心 (79,335)） | ⚠️ 同上 |
| 8 点「开始识别」 | `jy.post_click(hwnd, *jr.START_BUTTON)`，`START_BUTTON=(1431,743)`；本次实测按钮青块在 `(571,734)-(659,760)`，中心 **(615,747)** | ❌ **坐标已偏**（差 ~816px），投递消息也点不动 → 需改用真实鼠标 + 重新标定 |
| 8 等识别完成 | `recognize()` 轮询草稿 JSON 的 `materials.texts` 增长（本次 13 秒出 7 条） | ✅ 逻辑正确 |
| 9 调字号 | 无（手工步骤） | — 建议：烧录用 `jianying_style.STYLE`（字号 94 / MarginV 90），与剪映里的 10 无关 |
| 10 调字体 | 无（手工步骤）；烧录用 `jianying_style.FONT_NAME = JYgangbi` + `H3_JIANYING_FONT` | ✅ 已等价实现 |
| 11 逐句核对 | `correct_with_official()`：网易云官方歌词**只改文字、时间轴一字不动**，门槛随来源可信度（≥85% 用 0.6，70~85% 用 0.85） | ✅ 比手工更严（手工只肉眼比对） |
| 12 导出 | **不进剪映导出**：`jianying_style.burn()` 用 ffmpeg + libass 直接烧录 `最终成片_字幕版.mp4` | ✅ 有意为之（导出的分层覆盖窗口点不动） |

### 结论：自动化省掉的是"1→8"的 UI 操作，"9→12"用别的方式等价实现

手工流程真正的价值是**第 8 步的时间轴**（剪映云端识别，最准）——这一点两条链路共用。

## 四、自动链路当前的真实卡点（按优先级）

1. **`START_BUTTON` 坐标失效**：代码里是 `(1431,743)`，实测按钮在 `(615,747)`。
   只改数字还不够——**投递消息点不动自绘按钮**，应改为"真实鼠标渐进移动 + 停顿 + 点击"，
   并且点击前用 `AttachThreadInput` 抢前台 + 校验前台窗口。
2. **`TEXT_TAB` / `RECOGNIZE_ITEM` 同风险**：本次我用真实鼠标在同坐标点成功，
   但代码走的是 `post_click`；建议统一换成真实鼠标点击（保留坐标，仅换点击方式）。
3. **截图不可用于判定**：`recognize()` 以草稿 JSON 为准（正确）；但任何新增的"看画面判断"逻辑都要避开
   `grab_screen`（会抓到遮挡窗口）与可能陈旧的 `capture()`。
4. **导出目录**：自动链路产物直接落 `SUBTITLE_OUT_DIR/{job}_字幕版.mp4` 并拷进发布目录；
   手工导出若要走剪映，记得把「导出至」改成对应发布目录，别落在 `9月16日 (10).mp4` 这种默认命名上。
