# H3 MotionStudio 全流程自动化 —— 设计方案

> 目标：把你目前「人工在 H3 网页点一遍 + 人工去 Codex 聊天传图生成 + 人工等发布成品目录」的重复劳动，做成一条尽量无人值守的 Python 自动化流水线。
> 本文件是**方案文档**（不是实现）。确认后我再按它落地代码。

---

## 0. 先说清楚「H3」是什么（这是最关键的一条）

**结论：你要操作的「H3 软件」，就是当前这个项目本身（H3 影动高清工作台），不是某个独立的第三方桌面程序。**

证据：

- 项目就叫 H3 MotionStudio，启动脚本标题就是「H3 影动高清工作台」，页面侧边栏第一项就是「**影动生成**」，其下就是「**批量制作**」（`/batch` 路由）。
- 你列的 H3 动作——打开软件 / 点影动生成 / 点批量制作 / 填链接 / 点准备任务 / 读列表状态（待确认）/ 点确认出片——**在 `/batch` 页面里就是前端对后端 API 的一连串调用**，项目已经把整套流程 API 化了。
- 「发布成品」目录 `E:\AI_Exports\H3-MotionStudio\发布成品\` 就是项目批量制作的真实输出。

**所以：H3 这一环根本不需要 pywinauto / uiautomation / AutoHotkey 去识别屏幕点按钮。** 直接调用项目自己的后端 HTTP API 即可，又快又稳，还不受窗口焦点、分辨率、元素坐标漂移影响。

这一步推翻了你原方案里的「方式 A（读界面）」，直接采用你说的「方式 B（看代码 / 接口 / 本地数据）」——而且比你想的更彻底：**不是读数据库，而是直接调项目自身公开的 API**。

## 1. 整体架构

```text
┌──────────────────────────────────────────────────────────────┐
│                    Python 自动化流水线 (orch.py)                │
│  全部用 httpx 直连项目后端 http://127.0.0.1:8111/api           │
└──────────────────────────────────────────────────────────────┘
     │ 1) 建批次/准备任务/轮询状态/确认出片（调 /api/batches/*）
     │ 2) 抽帧选"人物最完整"帧（ffmpeg + OpenCV）
     │ 3) 读桌面提示词 txt + 备料三件套（已有：出图提示词/图一/图二）
     │ 4) Playwright 打开 Codex → 上传图一+图二+提示词 → 生成 → 下载成图
     │ 5) 把 Codex 成图上传回项目（POST /items/{id}/image）
     │ 6) watchdog 监听发布成品目录 → 检测 发布文案.txt + 人物图.png
     │ 7) 封面生成（Codex 同一聊天，先 4:3 后 3:4，严格串行）
     ▼
   发布成品/{编号}_{标题}_{作品号}/  ← 最终成片.mp4 + 人物图.png + 发布文案.txt
```

**推荐技术栈（全部 Python）**：

| 环节 | 选型 | 替代 |
|---|---|---|
| H3 操作 / 状态检测 | `httpx` 直调后端 API | ~~pywinauto / uiautomation / AHK~~（不需要）|
| 抽帧 + 挑帧 | `ffmpeg` + `opencv-python` | — |
| 读提示词 txt | Python `pathlib` 读文件 | — |
| Codex 浏览器自动化 | `playwright`（复用已登录浏览器 Profile）| Selenium |
| 监听发布成品目录 | `watchdog` | 轮询 glob |
| 配置 | `settings` 环境变量 + `config.json`（路径做成配置项）| 硬编码 |

> 依赖需新增：`watchdog`、`opencv-python`、`playwright`（仅以上三个）。后端已装 `httpx`、`pillow`。

## 2. 各环节详细方案

### 环节 1：H3 操作 —— 直调后端 API

后端 `backend/app.py` 已提供整套批量 API（已核对）：

| 动作 | API |
|---|---|
| 建批次 + 准备任务 | `POST /api/batches`（body 含 `singingLinks` / `danceLinks`、`singingRatio`/`danceRatio`）|
| 追加链接 | `POST /api/batches/{id}/items` |
| 读批次/列表状态 | `GET /api/batches/{id}`（条目状态含 `awaiting_review`=待确认）|
| 确认出片（单条/多条）| `POST /api/batches/{id}/items/{item_id}/confirm`、`/confirm-many` |
| 跳过 / 删除 / 重试 / 回到确认 | 对应 `skip` / `delete` / `retry` / `reopen-review` |
| 换候选人物图（上传 Codex 成图）| `POST /api/batches/{id}/items/{item_id}/image`（multipart `file`）|
| 打开发布目录 | `POST .../open-output` |

**「待确认」状态检测**（你问的核心）：
- 轮询 `GET /api/batches/{id}`，读每条 `item.status`。
- 项目里 `awaiting_review` 在界面上就叫「**待确认**」；`confirmed` = 已确认放行、`running`/`revising` = 出片中、`completed` = 已完成、`failed`/`skipped` = 失败/跳过。
- 比起识别界面状态列，直接读 API 返回的 `status` 字段 100% 准确、无 OCR 误差。

**建议**：自动化脚本**不抢占**你在网页上的手动操作。两种运行模式二选一：
- **A. 驱动模式**：脚本自己建批次、填链接、确认出片，全程无人。
- **B. 辅助模式**：你仍然在网页上填链接点「准备任务」，脚本只做两件事——① 轮询到某条 `awaiting_review` 且已有候选图就调用 `/confirm`；② 处理后续 Codex 传图与封面。

（推荐先做 B，风险最低，人仍可控。）

### 环节 2：视频抽帧 + 挑"人物最完整"帧

你明确要求「**不是只抽第一帧**」。

**抽帧策略**（`frame_picker.py`）：
1. `ffprobe` 取视频时长 `T`。
2. 每隔 `T/10` 抽一帧（约 9~10 帧，覆盖全时段），保存为 JPEG。若你想保留全分辨率，另存一张联系表（6 帧）作为兜底。
3. 用 OpenCV **自动挑帧**，打分规则（从简单到复杂渐进）：
   - **V0（必做）**：人脸检测（Haar Cascade / 自带 `cv2.CascadeClassifier`）→ 选「人脸框最大 / 人脸居中 / 面积占比在合理区间」的帧。
   - **V1（可选，更准）**：清晰度（Laplacian 方差）> 阈值才算，避免运动模糊帧。
   - **V2（可选，进阶）**：眼开度检测（避免闭眼）、遮挡检测（避免手挡脸）——这两条需要额外模型（如 dlib / mediapipe），先不做，留作以后增强。
4. 输出：`scene-frame.jpg`（挑中的那一帧）+ 记录每帧的评分日志。

**注意**：项目 `batch_worker._prepare_review_work` **已经抽了 `scene-frame.jpg`（全分辨率场景帧）+ `source-contact-sheet.jpg`（6 帧联系表）**。环节 2 的「挑帧」如果要**喂给 Codex 作图一**，建议直接复用项目备料产出的 `scene-frame.jpg`，不必重复抽。**是否要另抽多帧给 Codex 选，做成可配置项**（默认复用项目已抽的图一）。

### 环节 4：ChatGPT 桌面端自动化（Playwright + CDP，已实测可行）

> **2026 实测结论**：目标桌面端是**微软商店（MSIX）打包的 Electron/Chromium 应用**，包名 `OpenAI.Codex`（原 Codex Desktop 改名）。用 `--remote-debugging-port` 启动后，**CDP 调试端口能正常开放**（实测返回 `Chrome/152.0.7977.83` 与 `webSocketDebuggerUrl`）。因此可以用 **Playwright 通过 CDP 直接接管它的聊天界面**，在 DOM 上定位输入框、上传图片、粘贴提示词、读结果、下载成图——**不需要识别屏幕、不需要 pywinauto 点坐标**，稳定性和可维护性都高一个数量级。

**关键技术事实（已核实）**：
- 可执行文件：`C:\Program Files\WindowsApps\OpenAI.Codex_26.908.4834.0_x64__2p2nqsd0c76g0\app\ChatGPT.exe`（MSIX 目录受 ACL 保护，只读）
- **真实用户数据目录（登录态在此）**：`C:\Users\admin\AppData\Local\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Roaming\Codex\web\Codex`
- 启动即复用登录态：用它作为 `--user-data-dir` 启动，**无需重新扫码登录**

**自动化启动方式（关键，唯一的"侵入点"）**：
- 要让调试端口生效，应用**必须以 `--remote-debugging-port=<端口>` 启动**。而你当前正在运行的会话**没有开这个端口**。
- 所以自动化流程先做一次引导：**完全退出桌面端 → 用带调试端口 + 真实 profile 的方式重启它** → 等待 `http://127.0.0.1:<端口>/json/version` 就绪 → Playwright `connect_over_cdp` 接管。
- 之后用户平时照常用这个窗口；退出再重启即可再次进入可自动化状态。
- ⚠️ 这条必须**得到你同意**才会执行（会重启你的 ChatGPT 桌面端），而且重启后登录态仍在、不丢会话。

**Playwright 驱动流程**（`codex_automation.py`）：
1. 引导：确保桌面端关闭 → 用调试端口 + 真实 profile 拉起 → 等 CDP 就绪 → `connect_over_cdp`。
2. 每个任务 = 在「聊天」标签页新建会话 → `set_input_files`（图一+图二）→ 粘贴提示词 → 发送 → **轮询等回复完成**（不靠固定 sleep）→ 取到生成图片 → 保存到条目目录 → 回到该聊天（供封面复用）。
3. **与项目 manual 模式衔接**：Codex 成图落盘到 `data/batches/{batch}/{item}/` 后，调用 `POST .../items/{item}/image` 上传，项目自动重写文案并写进发布目录的 `人物图.png`。

**风险点与对策**：
- **桌面端重启**：唯一侵入点，先征得同意，重启不丢登录态。
- MSIX 包升级会变安装路径 → 自动探测最新 `WindowsApps\OpenAI.Codex_*\app\ChatGPT.exe`，别硬编码。
- DOM 结构/选择器可能随版本变化 → 用 `data-testid`/稳定文本定位，选择器集中一个文件；失败截图存档。
- 等待生成不可用固定秒数 → 轮询「回复完成/停止生成按钮消失」标志。
- 并发 → **严格一次一条**（一个登录态，别并行开多个聊天）。
- 兜底：若未来 Codex/ChatGPT 提供正式 API，可替换成 API（接口留抽象层）。

### 环节 5：监听「发布成品」目录（watchdog）

**背景**：项目在**审核点**就会把 `人物图.png + 发布文案.txt` 提前写进发布目录，成片跑完再补 `最终成片.mp4`（`deliver_review_materials()`，已核对源码）。

**方案**：`watchdog` 观察 `E:\AI_Exports\H3-MotionStudio\发布成品\`，对每个新出现的条目子目录：
- 检测 `人物图.png` 与 `发布文案.txt` **是否都出现** → 触发封面生成流程（环节 6）。
- 检测 `最终成片.mp4` 出现 → 该条完整交付，归档/记录。

> 注意：`人物图.png` + `发布文案.txt` 在审核点就有了，所以**封面生成可以在出片的同时进行**（不冲突）；真正要等的是成片（出片后补）。方案里封面流程触发条件是「人物图 + 发布文案齐了」，不受成片是否完成限制。

### 环节 6：封面生成（回到同一 Codex 聊天，严格串行）

**规则（你已定死）**：
- 回到**同一个** Codex 聊天（不是新开）。
- 上传 `发布文案.txt` + `人物图.png`。
- **先做 B站 4:3，完成后再做抖音 3:4，不能并行**。
- 这个顺序写成硬规则（代码里固定，不做成可并行）。

**方案**：Playwright 在环节 4 那个 Codex 聊天里继续追加消息：上传发布文案 + 人物图 → 发「生成 B站 4:3 封面」→ 等结果 → 存图 → 再发「生成抖音 3:4 封面」→ 等结果 → 存图。存图路径进入条目发布目录（或单独封面目录，可配置）。

所有脚本放在 `automation/` 目录，**独立于现有 `backend/`**，不侵入项目主代码（后端已有完整批量 API，无需改它）。

## 5. 实现顺序（建议分 5 步，逐步验收）

1. **Step 1 —— H3 API 客户端**：`h3_client.py` 打通建批次/轮询/确认/上传图，先跑通「读状态 → 确认出片」。**验证点**：脚本能在真实批次上正确读到 `待确认` 并确认。无 GUI 风险，最先做。
2. **Step 2 —— 提示词 + 抽帧**：`prompts.py` + `frame_picker.py`，读 txt + 抽帧挑帧。
3. **Step 3 —— 桌面端自动化（已实测 CDP 可行，见环节 4）**：`codex_automation.py`，引导重启桌面端 → 接管聊天 → 上传图一+图二+提示词 → 拿到生成图。**先手动跑一次确认能传图、能取到图**。
4. **Step 4 —— 目录监听 + 封面流**：`publish_watcher.py` + `cover_flow.py`。
5. **Step 5 —— 编排**：`orch.py` 串起来，配 `config.json`，出 README。

## 9. 后端集成（图片流程自动化，已接入「点准备任务自动跑」）

> 2026-09 用户确认：批量制作其他环节都已完成，**只需自动化图片流程**（人物图 + 两张封面），
> 且**严格单链路、一条一条完成，绝不并发**。

### 9.1 新增模块 `backend/chatgpt_image.py`

把「图片流程」接进后端，点「准备任务」后自动跑。原理：ChatGPT 桌面端是 MSIX 打包的
Electron/Chromium 应用，用 `--remote-debugging-port` 启动后 CDP 端口可开（**已实测**），
Playwright `connect_over_cdp` 直接接管聊天界面，在 DOM 上上传图/粘贴提示词/取回成图。

**全局图片锁 `_IMAGE_LOCK`（asyncio.Lock）**：所有图片生成（候选人物图 + 封面）共用一个锁，
同一时刻只跑一条，前一条没跑完下一条不开始 —— 满足「一条一条完成」。这是独立于
`pipeline_lock`（视频/ComfyUI）的第二把锁：图片不阻塞视频出片，但所有图片操作彼此串行。

**两条流程**：
1. **候选人物图**：`_prepare_review_work` 备料完、manual 模式且还没候选图时，把
   `图一(scene-frame.jpg) + 图二(本人固定参考.png) + 出图提示词.txt` 送进桌面端生成，
   取回成图后 `POST /items/{id}/image` 上传回该条目（自动重写文案 + 落盘人物图）。
2. **封面**：人物图 + 发布文案落盘后，`_maybe_spawn_covers` 后台触发，回到同一聊天
   依次生成 B站4:3 → 抖音3:4（严格串行，写死顺序）。

**单链保证**：候选人物图在 `_prepare_review_work` 里被 inline await（runner 逐条处理），
封面后台任务与任何图片操作都抢 `_IMAGE_LOCK`，所以全流程图片严格一条一条。

**失败处理**：生成失败/超时一律标黄停下等人工，绝不自动用差图顶替、也不抛断 runner。

### 9.3 「让 AI 换一张」按钮（页面手动触发换图）

在候选人物图旁边加了两个入口（`editable` 状态下显示，即未完成且非出片中）：

- **「AI 换一张」**：把图一+图二+提示词再送一次 ChatGPT，生成一张**全新的**候选图并替换。
- **「写意见再换」**：展开输入框写修改意见（如「换暖色背景、换发型」），把**当前候选图**
  + 图二 + 提示词 + 意见一起送 ChatGPT，让它**基于这张重出一版**。

实现：
- 接口 `POST /api/batches/{id}/items/{id}/regen-image`（body 可选 `{feedback}`）。
- 校验与换图一致：`completed`/`deleted` 拒绝（409 已结束）、`running`/`revising` 拒绝（先取消）、
  需要 `H3_AUTO_CHATGPT_IMAGE=1`、正在生成时拒绝重复触发。
- **异步**：接口立即返回，后台任务生成；条目 `ai.image_generating=true` 期间前端按钮变
  「正在生成…」并禁用，生成结束（WebSocket 推送该标记消失）后自动刷新显示新图。
- 受 `_IMAGE_LOCK` 单链保护：和自动生成、封面严格串行，绝不并发。
- 失败仍标黄停下等人工，不会用差图顶替。
